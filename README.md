# FinCalc

A browser-native personal finance decision tool for Indian households.

Every calculator in the market answers "what is my EMI". FinCalc answers the question a household
actually has: **given the same monthly outflow, which allocation leaves me wealthier, more liquid and
less fragile in 5, 10, 15 or 25 years — after tax, transaction costs and realistic exit friction?**

It compares up to four scenarios (a bigger flat on a bigger loan; keeping the flat, renting nearer work
and buying a plot; keeping the flat and buying listed REITs or index funds…) on equal outflow, and leads
with a **hurdle rate** — "this plot needs to compound at 12.4% for 15 years to beat an index fund" —
rather than a forecast.

Live site: <https://archishman-b.github.io/FinCalc/>

## Principles

1. **Equal outflow.** Scenarios are only compared on identical monthly cash; any difference is invested in a stated default instrument and counted.
2. **After tax and after cost.** Stamp duty, registration, GST, brokerage, maintenance, property tax, vacancy, exit brokerage, capital gains — and tax applied every year during accumulation, not only at exit.
3. **Ranges, not points.** Bear / base / bull for every projection, Monte Carlo where the engine supports it.
4. **Symmetric assumptions.** A Parity Auditor flags growth rates, reinvestment, tax timing and transaction costs that differ across scenarios, and can equalise them in one click.
5. **Assumptions are first-class.** Every number is inspectable: its value, where it came from, and when it was last verified.
6. **Privacy by architecture.** All computation is client-side. No backend, no accounts, no telemetry. Scenarios live in your browser and travel as URLs.
7. **Information, not advice.** FinCalc is not SEBI- or IRDAI-registered investment advice. It shows the maths; you decide.

## Repository layout

```
packages/engine   Pure TypeScript financial engine. Zero DOM, zero React, zero I/O (lint- and tsconfig-enforced).
packages/data     Versioned JSON rule packs keyed by financial year; every figure carries a source URL and a verifiedOn date.
packages/ui       Shared presentational primitives and formatters (₹12,34,567 / ₹1.23Cr).
apps/web          Vite + React + TypeScript site, deployed to GitHub Pages from /docs.
apps/mobile       (Phase 10) Expo app importing the engine unchanged.
docs/             Build output served by GitHub Pages. Committed; regenerated by `npm run build`.
```

## Development

Requires Node 22 (see `.nvmrc`).

```
npm install          # once, and after dependency changes
npm run dev          # Vite dev server for apps/web — keep it in its own terminal tab
npm run test         # Vitest, whole monorepo
npm run typecheck    # tsc --noEmit per package (the engine compiles against ES2022 only)
npm run lint         # ESLint, including the engine boundary rules
npm run check        # lint + typecheck + test + build
```

The committed `package-lock.json` is generated with every platform's native binaries recorded
(rolldown, lightningcss, tailwind oxide for macOS, Linux and Windows), so `npm ci` installs
correctly on a Mac, in CI and in a Linux container from the same file with no lockfile churn.

## Deploying

`npm run build` writes the site straight into `/docs` (Vite `outDir`), so the release flow is:

```
npm run build
git add -A && git commit -m "release: …"
git push
```

GitHub Pages is configured to serve `main` → `/docs`. The Vite `base` is `/FinCalc/`; if the site
ever moves to a custom domain, change `base` and add redirects — shared scenario URLs depend on it.
